감상노트 보고서 반영 요청 (2026-11-16 개발 변경분)
====================================================

오늘 개발에서 보고서 내용에 영향을 주는 변경을 정리했습니다.
DB 스크립트 변경은 8장·11장, 나머지는 해당하는 장(기능 설계, API, 구현, 배포, 한계)에 반영해 주세요.
코드와 스크립트는 GitHub main 브랜치에 모두 올라가 있습니다.


1. 외부 작품 API 결정 변경
----------------------------------------------------
- 영화: TMDB (변경 없음, 연동은 아직 남음)
- 도서: 알라딘 → YES24로 변경 (알라딘 TTB 키 발급이 종료됨)
  * 주의: YES24는 공식 공개 API가 있는지 아직 확인되지 않았습니다. 문서나 키를 받은 팀원이 확인해 주세요.
    공개 API가 없다면 도서는 다른 방법을 정해야 하고, 보고서에도 그에 맞게 적어야 합니다.
- 공연: KOPIS(공연예술통합전산망) 오픈API로 확정, 연동 완료


2. DB 변경 (8장 테이블 정의, 11장 스크립트)
----------------------------------------------------
[work 테이블] 외부 출처 컬럼 2개 추가
  - source       VARCHAR2(10)  NULL  : 작품을 가져온 출처 'TMDB' / 'YES24' / 'KOPIS' (샘플 작품은 NULL)
  - external_id  VARCHAR2(40)  NULL  : 출처 쪽 작품 ID (예: KOPIS 공연ID 'PF304730')
  - 제약조건
      ck_work_source       : source IN ('TMDB','YES24','KOPIS')
      ck_work_source_pair  : 두 컬럼이 둘 다 NULL이거나 둘 다 값이 있어야 함
      uq_work_source_ext   : UNIQUE(source, external_id) → 같은 외부 작품을 두 번 저장하지 못함

[users 테이블] 비밀번호 해시 컬럼 추가 (자체 가입/로그인)
  - password_hash  VARCHAR2(100)  NOT NULL : BCrypt 해시(60자). 비밀번호 원문은 저장하지 않음
  - 샘플 회원 12명은 모두 시연용 비밀번호 'gamsang1234'의 해시로 채움

[스크립트]
  - 01_schema.sql, 02_seed.sql에 위 내용 반영 (Oracle, Turso 둘 다)
  - 이미 만든 DB에 적용하는 마이그레이션 스크립트 추가
      db/06_add_work_source.sql      (work 외부 출처 컬럼)
      db/07_add_password_hash.sql    (users 비밀번호 해시)
      db/turso/ 아래에 같은 이름의 Turso(SQLite)용 파일
  - person, work_person 테이블은 구조 변경 없이 이번에 앱에서 처음 사용함


3. 기능 추가
----------------------------------------------------
[자체 가입/로그인]
  - 이메일·닉네임·비밀번호로 가입, 이메일·비밀번호로 로그인, 로그아웃
  - 비밀번호: BCrypt 해시로 저장(비밀번호마다 다른 salt, 일부러 느린 계산 → DB가 유출돼도 원문 추측이 어려움)
  - 로그인 유지: 서버 세션 + 세션 쿠키(JSESSIONID)
      HttpOnly(자바스크립트로 읽을 수 없음), SameSite=Lax(다른 사이트 요청에 실리지 않음, CSRF 방지),
      배포판은 Secure(https로만 전송)
  - 로그인할 때 세션을 새로 만듦(세션 고정 공격 방지)
  - 로그인 실패 시 "이메일 또는 비밀번호가 맞지 않습니다"로만 안내(가입된 이메일 추측 방지)
  - 이전에는 요청에 회원 번호(userId)를 담아 보냈지만, 이제는 모든 API가 로그인 세션에서 회원을 확인함
    → 다른 사람 번호로 요청할 수 없음. 남의 기록 수정·남의 기록에 후기 작성은 403
  - 로그인하지 않으면 작품 목록·상세·장르·KOPIS 검색만 가능, 나머지는 401
  - 시연용 계정: user01@example.com ~ user12@example.com / 비밀번호 gamsang1234

[KOPIS 공연 검색·가져오기]
  - 작품 화면 '공연' 탭에서 제목으로 KOPIS 공연을 찾고 '가져오기'를 누르면 우리 DB에 저장
  - 저장되는 것: work(source='KOPIS'), performance(공연장·기간), work_genre(장르 이름으로 매칭),
    person/work_person(출연 최대 8명, 제작진 최대 4명)
  - 이미 가져온 공연은 다시 저장하지 않고 기존 작품을 엶 (UNIQUE 제약 활용)
  - 출처 표시: "공연 정보 출처: (재)예술경영지원센터 공연예술통합전산망(www.kopis.or.kr)"
    → 참고문헌에도 KOPIS 오픈API를 추가해 주세요

[친구]
  - 내가 보낸 대기 중 요청 목록과 '요청 취소' 추가
  - 요청 후보에서 이미 친구이거나 요청을 주고받는 중인 회원은 제외

[작품 상세]
  - 참여한 사람(감독, 배우, 저자, 작곡, 출연 등)을 역할별로 표시 (work_person 사용)


4. API 변경
----------------------------------------------------
[추가]
  POST /api/auth/signup          가입(가입 후 바로 로그인)
  POST /api/auth/login           로그인
  POST /api/auth/logout          로그아웃
  GET  /api/auth/me              로그인한 회원 정보(아니면 401)
  GET  /api/works/kopis?q=       KOPIS 공연 검색
  POST /api/works/kopis/{공연ID}  KOPIS 공연을 DB에 저장하고 작품 상세 반환
  GET  /api/friends/requests/sent  내가 보낸 대기 요청

[변경]
  - 모든 API에서 userId, viewerId 파라미터와 요청 본문의 userId가 빠짐(로그인 세션으로 대체)
    예) GET /api/records?userId=1  →  GET /api/records
  - 친구 요청 본문은 {receiverId}만, 수락은 {requesterId}만 보냄
  - GET /api/works/{id} 응답에 source(외부 출처), people(이름·역할 목록) 추가


5. 배포(Turso) 관련 한계 — 배포 또는 한계 장, 부록
----------------------------------------------------
- 배포용 DB(Turso)에 접속하는 JDBC 드라이버(libSQL, 최신 1.0.9까지 동일)에 결함이 있어 앱에서 우회함
  * 트랜잭션(commit/rollback)을 지원하지 않음 → 배포판은 SQL 문장마다 즉시 저장(자동 커밋)
    서비스 중간에 오류가 나도 앞에서 실행한 문장은 되돌아가지 않음.
    (앱의 쓰기는 대부분 SQL 한 문장이라 시연에는 지장 없음. Oracle 로컬 버전은 정상적으로 트랜잭션 사용)
  * INSERT 후 생성 키 반환을 지원하지 않음 → INSERT ... RETURNING 문으로 대체
  * 변경된 행 수를 잘못 돌려줌(인덱스 쓰기까지 셈) → 앱에서 보정
- 보고서의 논리·물리 모델은 Oracle 기준 그대로이고, Turso 스크립트는 배포용 이식본입니다.
- Render 무료 플랜은 15분간 요청이 없으면 잠들고, 깨어날 때 약 1분 걸림.
  깨어나면 로그인 세션이 사라져 다시 로그인해야 함 → 시연 5분 전에 사이트를 한 번 열어 둘 것


6. 알려진 한계 (한계·향후 과제에 반영)
----------------------------------------------------
- 로그인 시도 횟수 제한이 없음(공개 운영이라면 필요)
- KOPIS 검색은 기간이 필수이고 최대 31일이라 "오늘 앞뒤 15일 동안 공연하는 작품"만 찾을 수 있음
- KOPIS 줄거리는 글 대신 소개 이미지로 제공되는 경우가 많아, 줄거리가 비어 있는 공연이 있음
- KOPIS에서 가져온 사람은 같은 이름이어도 작품마다 따로 저장함(동명이인을 잘못 합치지 않으려는 선택)
- 영화(TMDB)·도서(YES24) 연동은 아직 남아 있음
