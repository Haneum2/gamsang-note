# 감상노트 DB (Oracle) 실행 안내

물리적 데이터 모델(MySQL 8) 문서를 Oracle 문법으로 옮긴 DB 스크립트다. 대상은 **Oracle 12.2 이상**(19c, 21c XE 권장)이고, 모든 파일은 **UTF-8**이다.

## 실행 순서

| 순서 | 파일 | 내용 |
| --- | --- | --- |
| (0) | `00_drop.sql` | 재실행용 초기화. 처음 실행할 때는 건너뛴다. |
| 1 | `01_schema.sql` | 테이블 16개, 제약조건, 인덱스 |
| 2 | `02_seed.sql` | 샘플 데이터 + 식별 컬럼 번호 재설정 |
| 3 | `03_views_triggers.sql` | 뷰 2개, 트리거 1개 |
| 4 | `04_queries.sql` | 핵심 쿼리 13개 (보고서 캡처용) |
| 5 | `05_constraint_tests.sql` | 제약조건·트리거 동작 확인 (오류가 나는 것이 정상인 문장 포함) |

SQL Developer에서는 스크립트 실행(F5)으로 한 파일씩 돌리고, SQL*Plus에서는 `@01_schema.sql`처럼 실행한다. 한글이 깨지면 SQL*Plus 실행 전에 `chcp 65001`과 `SET NLS_LANG=KOREAN_KOREA.AL32UTF8`을 설정한다.

| 항목 | 건수 | 항목 | 건수 |
| --- | --- | --- | --- |

| 장르 | 21 | 좋아요 | 154 |

## MySQL 문서 대비 바뀐 점

| 항목 | MySQL 문서 | Oracle 스크립트 |
| --- | --- | --- |
| 자료형 | INT, VARCHAR, TEXT, DATETIME | NUMBER(10), VARCHAR2(n CHAR), CLOB, TIMESTAMP(0) |
| 자동 증가 | AUTO_INCREMENT | `GENERATED BY DEFAULT AS IDENTITY` |
| ENUM | ENUM(...) | VARCHAR2 + CHECK (컬럼 IN (...)). 후기 공개 범위·기록 상태 등에 `ck_...` 제약을 추가 |
| 삭제 규칙 RESTRICT | ON DELETE RESTRICT | 절을 생략(Oracle 기본값이 같은 동작) |
| 인덱스 | KEY 로 테이블 안에 선언 | 별도 `CREATE INDEX` (Oracle은 외래키 인덱스를 자동 생성하지 않음) |
| 반대 방향 친구 요청 차단 | 트리거 `trg_friendship_no_reverse` | **함수 기반 유일 인덱스** `uq_friendship_pair` 로 대체. Oracle에서는 같은 테이블을 조회하는 행 트리거가 변경 중 테이블 오류(ORA-04091)를 낼 수 있어서다. |
| 뷰 | `v_friend_feed` | 동일하게 유지 + 공개 범위를 viewer 기준으로 적용하는 `v_visible_review` 추가 |
| 쿼리 문법 | `LIMIT`, `DATE_FORMAT` | `FETCH FIRST n ROWS ONLY`, `TO_CHAR` |
| 추가 CHECK | 없음 | 상영시간·쪽수가 양수인지 확인 (MySQL의 UNSIGNED 대응) |

테이블 이름은 MySQL 문서와 같이 `users`, `comments`를 쓴다. `USER`, `COMMENT`는 Oracle 예약어라 그대로 쓸 수 없다. 논리 모델 문서의 `USER`, `COMMENT`와 이름이 다르다는 점을 보고서(정규화·물리 모델 장)에 한 줄 적어 두면 좋다.

## 확인 상태와 한계

- **Oracle에서 직접 실행해 보지는 못했다.** 작업 환경에 Oracle이 없어서, 같은 제약조건을 SQLite로 옮겨 샘플 데이터 적재(외래키·UNIQUE·CHECK 포함), 무결성 점검, 쿼리 로직, 뷰 가시성, 트리거 동작을 검증했다. Oracle 전용 문법(IDENTITY, 함수 기반 인덱스, 트리거, `FETCH FIRST`, `LISTAGG`)은 실행해 보지 않았으므로 오류가 나면 메시지를 알려 달라.
- `02_seed.sql` 끝의 `ALTER TABLE ... START WITH LIMIT VALUE`는 직접 번호를 넣은 뒤 식별 컬럼의 다음 번호를 맞추는 구문이다. 이 구문이 오류가 나면 같은 자리에 주석으로 넣어 둔 `START WITH n` 대체 구문을 쓴다. 이 단계를 건너뛰면 앱에서 새 행을 저장할 때 1번부터 다시 발급되어 기본키 중복 오류가 난다.
- 작품 데이터는 시연용이다. 제목·인물·연도·상영시간은 직접 정리한 값이라 TMDB·도서 API와 대조가 필요하고, 개봉·출간일은 연도만 맞추고 1월 1일로 통일했다. ISBN·쪽수는 비워 두었고, 공연장·공연 기간은 임의 값이다. 회원·기록·후기 등은 모두 임의 생성한 테스트 데이터다.
- 작품 종류(`work.type`)와 서브타입 행이 서로 맞는지는 DB가 막지 않는다. 예를 들어 `type='BOOK'`인 작품에 `movie` 행이 붙는 것을 허용한다. 샘플 데이터에서는 맞는 것을 확인했고, 앱 코드에서 지키거나 보고서의 개선 과제로 적을 수 있다.
